# S2.4 — Dominios de salón (Tutis + Galaxy)

> **Estado:** código listo · DNS/Vercel pendiente de aplicar  
> **Proyecto Vercel:** app (Citabella / `citabella-eight`), **no** `gotacheck-marketing`

## Objetivo

| Dominio | Muestra | Slug |
|---------|---------|------|
| `estudiotutis.com` (+ `www`) | Vitrina Tutis | `salon-tutis` |
| `galaxybarberiagt.com` (+ `www`) | Vitrina Galaxy | `galaxy-barberia-infantil` |

Comportamiento en código (`src/lib/vitrina/hosts.ts` + middleware):

- `https://dominio/` → rewrite interno a `/vitrina/[slug]` (URL sigue siendo `/`)
- `https://dominio/agendar` o `/reservar` → `/reservar/[slug]`
- `/reservar/[slug]` en el dominio del salón sigue funcionando
- Links viejos en `citabella-eight.vercel.app/vitrina/...` **siguen vivos**
- `/login`, dashboard, etc. en dominio de salón → redirect al host de la app (`NEXT_PUBLIC_SITE_URL`)

## Checklist Vercel (proyecto app)

1. Confirmar **Vercel Pro** en el team del proyecto app.
2. Proyecto app → **Settings → Domains → Add**:
   - `estudiotutis.com`
   - `www.estudiotutis.com` (redirect al apex o viceversa; elige uno primario)
   - `galaxybarberiagt.com`
   - `www.galaxybarberiagt.com`
3. Copiar los registros que Vercel muestre (normalmente):
   - Apex: **A** → `76.76.21.21`
   - `www`: **CNAME** → el target que indique Vercel (ej. `cname.vercel-dns.com`)

## Checklist DNS (registrador)

1. Quitar A/CNAME viejos del hosting anterior (si existen).
2. Crear exactamente los registros de Vercel.
3. Si el DNS es **Cloudflare**: proxy **DNS only** (gris), no naranja, hasta que el dominio diga Valid + SSL OK.
4. Esperar a que cada dominio en Vercel pase a **Valid**.
